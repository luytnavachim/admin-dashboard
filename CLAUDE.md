# Admin Dashboard — context for Claude

Standalone web-dashboard voor Micha (eenmans-IT-bedrijf Triplet IT). Vervangt het inkoop-/verkoop-administratie-proces. In productie geen Cowork-afhankelijkheid: de frontend praat rechtstreeks met Microsoft Graph (OAuth/MSAL) en met **Moneybird** via een eigen Cloudflare Worker. Claude Haiku wordt server-side (in de Worker) gebruikt voor PDF-extractie.

**Live op:** `https://admin.triplet-it.nl/` — frontend draait op **Apache, eigen Hetzner-server** (`95.217.203.120`, webroot `/var/www/admin-dashboard`). GEEN GitHub Pages.
**Worker (API-backend):** `https://admin-dashboard.michavantuyl.workers.dev/`
**Repo:** `github.com/luytnavachim/admin-dashboard` (lokaal: `~/Documents/admin-standalone`)

> **Boekhouding = Moneybird.** Informer is volledig uitgefaseerd (juni 2026). Alle live flows lopen nu via Moneybird (`/mb/*`-proxy). De oude Informer-helpers staan deels nog ongebruikt in `index.html` (informerFetch, migrateContacts/Sales/Purchase, e.d.) maar worden nergens meer aangeroepen — mogen later weg.

## Architectuur

Browser (Apache @ Hetzner) → MSAL OAuth → Microsoft Graph (mail/agenda/mappen direct).
Browser → Cloudflare Worker `/mb/*` → Moneybird API v2 (CORS-proxy, token server-side).
Browser → Cloudflare Worker `/extract` `/extract-sales` → Anthropic API (PDF → JSON).
Browser → Cloudflare Worker `/projects` → Workers KV (projecten/uren, cross-device, beveiligd via Microsoft-login: Worker checkt Graph `/me`).
Browser → `localStorage` (projecten-offline-cache `projects_v1` + testfactuur-vinkje `proj-test-mode` + thema `admin-theme`).

Doorsturen vanuit shared mailboxes vereist Send-As/Send-on-Behalf op die mailbox.
- **Multi-mailbox**: `MAILBOXES` bovenaan script = micha@vantuyl.it + micha@, info@, administratie@, inkoop@, finance@ (triplet-it.nl) + michavantuyl@gmail.com (`provider: "gmail"`). Eerste = primair (agenda). `/me` voor primaire, `/users/{email}` voor shared.
- **Persoonlijke Microsoft-accounts (outlook.com)** — sectie MSA, `provider: "msa"` in `MAILBOXES` (michavantuyl@outlook.com, venebrugge16@outlook.com). Buiten de tenant → eigen login per account via dezelfde `msalInstance` met `authority: MSA_AUTHORITY` (consumers) en `MSA_SCOPES` (Mail.ReadWrite, User.Read); accounts delen de MSAL-cache. `userPath()` geeft `/msa/<email>`; `graph()`/`graphBinary()` lossen dat via `msaResolve()` op naar `/me/…` met het token van dát account en schrijven absolute `@odata.nextLink`s terug naar `/msa/<email>` (`msaRewriteNextLink`). `initAuth` filtert MSA-accounts (`msaIsMsaAccount`: tenant `9188040d-…` of adres in de msa-lijst) uit de werk-login. Knoppen in topbar (`#msa-connect-btns`, `msaUpdateUi`). Niet-gekoppeld → scanrapport "niet gekoppeld". **Azure-vereiste**: app-registratie → Authentication → Supported account types = "any organizational directory + personal Microsoft accounts" (`signInAudience: AzureADandPersonalMicrosoftAccount`), anders faalt de consumers-login met AADSTS50020/50194.
- **Archiefmap**: `PROCESSED_FOLDER_NAME = "Administratie"`, per mailbox op topniveau; afgehandelde mails gaan via `archiveMail(email)` → `archiveFolderFor()` naar `Administratie/<jaar ontvangst>/<senderFolderName>` (`PROCESSED_BY_YEAR`). Alle move-plekken (Verwerkt ✓, → Moneybird, bookRowWithPdf, doorsturen, recMoveMail) gebruiken `archiveMail`. `findFolderId` zoekt de archiefmap alléén op topniveau (`topOnly`) en hernoemt bij eerste gebruik een oude map uit `LEGACY_PROCESSED_FOLDER_NAMES` ("MoneyMonk Verwerkt") via `renameFolder` (Graph PATCH mailFolder; Gmail: label-rename incl. geneste labels). De scan slaat de hele archiefmap incl. submappen over.
- **Opschonen-tab** (sectie OPSCHONEN): eigen scanperiode `clDays()` (localStorage `opschoon_days_v1`, keuze 60/90/180/365 via `#cl-period`, default **180 dagen** — los van `SCAN_DAYS` van het Overzicht; `clScan.days` zorgt dat de cache bij periode-wissel vervalt; paginalimiet in `scanMailbox` schaalt mee met `days`). **Scanrapport**: `scanAllMailboxes` vult `lastScanReport` (per mailbox status ok/afgekapt/alias/fout/niet gekoppeld, opgehaald/meegenomen/uniek, overgeslagen mappen uit `out._report` van `scanMailbox`); `renderScanReport($("cl-report"), …)` toont dit als tabel boven de lijst. Eigen volledige scan `clScan` = `scanAllMailboxes(clDays(), { full: true })` → `scanMailbox(..., opts.full)`: Gmail zonder `GMAIL_SCAN_QUERY` (URL-param `gmailfull=1`, shim geeft die door aan `gmailQueryFromFilter(filter, full)`), Outlook inclusief Archief (`info.archiveIds` uit `mailboxFolderInfo`). Groepeert per afzender (`clSenderKey`, eigen adressen uit `SELF_EMAILS` uitgesloten). "Verwijder alles" → `clDeleteFromSender`: zoekt per mailbox álle mails van die afzender (Graph `$filter=from/emailAddress/address eq`, Gmail `gmailq=from:`), slaat mappen uit `mailboxFolderInfo().skip` over (Verzonden/Verwijderd/Administratie) en verplaatst naar Verwijderde items (`clTrashFolderId`; Gmail = `TRASH` → shim doet `messages.trash`). Regels = afzenders in localStorage `opschoon_rules_v1`; met `opschoon_auto_v1` = "1" passen zowel `loadAll` (Overzicht) als `renderCleaner` (na de Opschonen-scan) ze toe (`clApplyRules(all, true)`). Sortering lijst via `#cl-sort` (meeste mails / nieuwste eerst / A–Z); statusregel toont ook mails van eigen adressen (`SELF_EMAILS`) die niet getoond worden. Nooit hard delete.
- **Gmail-mailbox** (sectie GMAIL in `index.html`, na GRAPH API): `gmailGetMeta` cachet berichtmetadata in `_gmailMetaCache` (geheugen; invalidatie bij move/trash/isRead via `gmailMetaInvalidate`) zodat een herscan niet alle messages.get herhaalt; pacing `GMAIL_UNITS_PER_SEC` = 120. `scanMailbox` levert bij een fout ná de eerste pagina een deelresultaat (`_report.partialError`, status "afgekapt"). login via Google Identity Services (`GMAIL_CLIENT_ID`, scope `gmail.modify`, token alleen in sessionStorage, knop "Gmail koppelen" in topbar / hint in alert-area). `userPath()` geeft `/gmail`; `graph()` en `graphBinary()` sturen `/gmail/*`-paden naar `gmailShim()`/`gmailBinary()`, die de gebruikte Graph-endpoints vertalen naar de Gmail REST API: `mailFolders` = labels (geneste labels `A/B` = submappen, well-known inbox/sentitems/… = INBOX/SENT/TRASH/DRAFT/SPAM, "archive" = ARCHIVE = alleen INBOX-label weghalen), `messages?$filter` = `messages.list` met `after:/before:/has:attachment` + `GMAIL_SCAN_QUERY`, daarna per bericht `messages.get` (6 parallel, `fields`-beperkt) → Graph-vorm (`from`, `toRecipients`, `receivedDateTime`, `webLink`, `attachments`, `parentFolderId` = overslaan-label > INBOX > eerste eigen label > ARCHIVE), `move` = `modify` (label erbij, INBOX eraf), `isRead` = UNREAD-label, `forward` = nieuwe MIME-mail met de PDF/UBL-bijlagen opnieuw bijgevoegd via `messages.send`. Zonder token wordt Gmail in `scanAllMailboxes` overgeslagen (`gmailReadyForScan`).
- **Worker-beveiliging**: `/mb/*`, `/extract`, `/extract-sales` en `/api/*` vereisen een Microsoft-token (`Authorization: Bearer`, via `projAuthHeaders()`); de Worker checkt Graph `/me` (`requireMsUser`, 5 min cache) tegen dezelfde allowlist als `/projects`. `ALLOWED_ORIGIN` = admin.triplet-it.nl + localhost:8000. `.assetsignore` houdt *.md/informer.html uit de publieke Worker-assets.
- **Overzicht-scan**: geen trefwoord-`$search` meer; `scanAllMailboxes(SCAN_DAYS)` haalt alle mails van de laatste 60 dagen uit alle mappen (excl. Verzonden/Verwijderd/Concepten/Ongewenst/Archief + Verwerkt-map incl. submappen) mét bijlagenlijst. Alias-mailboxen (zelfde Inbox-id, bv. micha@triplet-it.nl = micha@vantuyl.it) worden één keer gescand; dedupe op `internetMessageId`. Niet-herkende PDF-mails staan onder 'Andere mails met PDF-bijlage'. `mbBookPurchaseFromExtracted` boekt niet dubbel (check op factuurnummer).

De Worker forwardt body + content-type ongewijzigd (dus ook multipart voor bijlagen) en zet `Authorization: Bearer MONEYBIRD_TOKEN`. `mbBase()` leidt de Worker-origin af via `projWorkerBase()` (niet meer uit de oude Informer-config).

## Deployen — BELANGRIJK

`git push` zet code op GitHub maar publiceert NIETS. Twee losse stappen:

- **Frontend** → de Hetzner-server moet `git pull` doen in `/var/www/admin-dashboard`. Dit gebeurt automatisch via het lokale **Deploy Dashboard** (`~/Documents/git-deploy`, `http://127.0.0.1:4000`): de Push-knop pusht naar GitHub en draait dan de `POST_PUSH_HOOK` voor `admin-standalone` (SSH `root@95.217.203.120` → `git pull --ff-only`). Handmatig kan ook: `ssh root@95.217.203.120 "cd /var/www/admin-dashboard && git pull --ff-only"`.
- **Worker** → `npx wrangler deploy` (alleen nodig als `worker.js` wijzigt; vereist `wrangler login`).

## Jarvis: foto's van internet en de grens van 16 gereedschappen (25 november 2026)

- **`web_foto`** (Worker, alleen lezen): haalt één afbeelding van een openbaar https-adres op en geeft die als base64 terug (`beeld`, `mime`, `bron`). Is het adres een pagina, dan de `og:image` van die pagina. Zelfde adrescontrole als `web_lezen` (`webAdresOk`, omleidingen via `webHaal`), hooguit 1,5 MB. Nodig omdat de Jarvis-pagina zelf geen afbeeldingen van buiten mag laden.
- **Maximaal 16 gereedschappen per aanvraag** in de Jarvis-pagina: bij 17 weigert Claude elke aanvraag ("at most 16 tools per call"). De pagina bundelt daarom verwante gereedschappen (`bundel()`: `huis`, `uren`, `opzoeken`) en heeft de vlag `NIEUW` voor `huis_beheer`, `netwerk_beheer` en foto's in `toon`. Nieuwe functie erbij: eerst tellen (`TOOLS.length`), liever een actie in een bestaand gereedschap dan een nieuw gereedschap.
- Een webpagina vanzelf openen kan de pagina niet (`window.open` wordt geweigerd); `toon` zet een knop op het scherm. Vanzelf openen vraagt een vaste opdracht in jarvis-brein op de Mac.

## Jarvis: een webadres openen in Chrome op de Mac (25 november 2026)

- De pagina roept `terminal_uitvoeren` aan met `opdracht: "open-webadres <adres>"` (bewust geen nieuwe functie: zo hoeft de koppeling niet opnieuw verbonden te worden). `mcpTerminalRun` controleert het adres (alleen http/https, geen inloggegevens), zet het in KV (`jarvis_open_url`, 90 seconden geldig) en start de vaste opdracht `open-webadres` op de brug.
- Die opdracht draait `node open-url.mjs` in deze map: het script haalt het adres één keer op via `POST /brug/open-url` (kop `x-brug-key`, de sleutel van de brug) en opent het met `open -na "Google Chrome" --args --new-window`.
- De opdracht staat in `~/Documents/jarvis-brein/brug.config.json` (door Micha zelf toegevoegd; die map is niet aan Claude te koppelen). Geen `wijzigt`: Micha wil dat pagina's direct opengaan, zonder ja.

## Jarvis: Chrome op de Mac bedienen (25 november 2026)

- De pagina stuurt via `terminal_uitvoeren` de opdracht `chrome {json}` (acties: tabs, lees, ga, klik, typ, scroll, terug). `chromeJob` in de Worker controleert de vorm en zet de opdracht klaar in KV; de vaste opdracht `open-webadres` draait `open-url.mjs`, dat hem ophaalt en via `osascript` uitvoert in het voorste Chrome-venster. Het antwoord staat als JSON op de laatste regel van de uitvoer.
- **De veiligheid zit in `open-url.mjs`, niet bij het taalmodel**: knoppen, links met een riskant woord (`RISICO`) en invullen-met-enter buiten een zoekveld geven eerst een voorvertoning en worden alleen uitgevoerd met `bevestigd:true`; dat stuurt de pagina pas mee na een ja van Micha in een volgend bericht (`pendingChrome`). Wachtwoorden, codes en betaalgegevens worden nooit getypt (`GEHEIM`). Gewone links, lezen, scrollen, zoeken en ergens heen gaan gaan direct.
- Eenmalig op de Mac nodig: in Chrome Weergave > Ontwikkelaar > "JavaScript van Apple Events toestaan", en de macOS-vraag of node Google Chrome mag bedienen toestaan.
- Bewust niet gebouwd: vrije terminalopdrachten. De pagina leest ook mail en webpagina's; een vrije shell zou één vergiftigde tekst genoeg maken om opdrachten op de Mac te draaien.
- **KV-valkuil (25 november):** een gelezen KV-waarde blijft tot een minuut in een tussenopslag. Met één vaste sleutel kreeg de Mac bij de tweede opdracht "er staat niets klaar". Nu krijgt elke opdracht een eigen sleutel (`jarvis_open:<tijd>:<willekeurig>`, verloopt na 2 minuten) en zoekt `/brug/open-url` de nieuwste met `list`; `open-url.mjs` probeert het tot acht keer.

## Jarvis op de Mac: Outlook, programma's en betrouwbare overdracht (25 november 2026, middag)

- **Durable Object `JarvisJobs`** (binding `JOBS`, migratie `v1` in `wrangler.jsonc`) bewaart de klaargezette opdracht tot de Mac hem ophaalt. KV liep achter (ook `list`), waardoor de Mac "er staat niets klaar" kreeg. Zonder de binding valt de code terug op KV (zo draaien de tests).
- **Nieuwe acties** via `chrome {json}`: `outlook` (`zoek`) haalt de Outlook-app naar voren, zoekt via het menu Bewerken > Zoeken > "Zoeken in Outlook-items" en klikt het bovenste resultaat aan; `app` (`naam`) opent een programma dat in een programmamap staat. De nieuwe Outlook voor Mac heeft geen script-ingang om één bepaalde mail te openen; dit loopt daarom via het scherm (System Events) en vraagt eenmalig Toegankelijkheid voor node in de systeeminstellingen. De menunamen zijn Nederlands.
- **Doelvenster:** Chrome-acties gaan naar het voorste venster dat niet Jarvis zelf is (`DOEL`); Jarvis staat immers voor zodra Micha ertegen praat.
- **Klikken:** alleen versturen (submit, knop in een formulier) en namen met een riskant woord (`RISICO`) vragen een ja. Menu's, tabbladen en gewone knoppen gaan direct. Ook elementen met `onclick`, `aria-haspopup`, `aria-expanded`, `role=option/treeitem` zijn klikbaar; bij meerdere treffers wint de kortste naam.
- **Outlook, zo werkt het echt (getest 25 november 14:50 op de Mac van Micha):** stap 1 zoekt via het menu en toetsen; stap 2 vindt het bovenste bericht via het vaste pad `table 1 of group 1 of splitter group 1 of splitter group 1 of splitter group 1 of window 1` (0,4 s) en klikt met een muisklik via CoreGraphics (JXA). Niet gebruiken: `click at` van System Events en zoeken door het hele venster; beide duren langer dan de 20 seconden die de brug een opdracht geeft. Verandert Outlook zijn opbouw: `outlook` met zoek `#diag 8` toont de rollen en maten, `#rij` meet alleen waar het bovenste bericht staat.
